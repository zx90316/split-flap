# ESP32 十字元架構

更新：2026-10-20。這是依實購品項建立的接線與韌體基準，不是已完成的實機。21 個採購品項均為交接快照中的「待出貨」；沒有點收、領用、燒錄或硬體測試紀錄。後續若有新庫存版本，應以新版本更新 [BOM](../../hardware/ordered-bom.csv)。

## 保留與替換的範圍

- 保留上游的 10 字元、每字元 45 片翻頁、滾筒、框架與外殼設計。印製件先試裝，不直接改變功能尺寸。
- 控制改成一片 P008 ESP-WROOM-32、現成模組與 P004 洞洞板。
- 不沿用上游每字元 Arduino Nano、客製 PCB、ESP-01 主控及其串接接線。倉庫內的舊資料只供追溯。

目前新韌體是 USB 序列控制原型；Wi-Fi／Web／NTP 尚未移植。操作命令及軟體預設值見 [韌體說明](firmware.md)。

## 訊號分工

```text
ESP32，3.3V 邏輯
  GPIO21 SDA ─ LV1 / HV1 ─ I²C SDA ─ 0x20、0x21、0x22、0x23
  GPIO22 SCL ─ LV2 / HV2 ─ I²C SCL ─ 四片 MCP23017，VDD=5V
  GPIO23 OD  ─ LV3 / HV3 ─ /RESET ─ 四片 MCP23017
                    P011，LV=3.3V，HV=5V，共地

  0x20：四組 4 位元輸出 → 字元 0–3 的 ULN2003
  0x21：四組 4 位元輸出 → 字元 4–7 的 ULN2003
  0x22：兩組 4 位元輸出 → 字元 8–9 的 ULN2003
  0x23：GPA0–6、GPB0–2 ← 十片 5V Hall 訊號
```

OD 代表開汲極輸出。GPIO23 拉低以重設 MCP，釋放後由各側上拉回到各側電源。高壓側 /RESET 的上拉不可直接接到 ESP32。

本版取代交接中的「3 片 MCP＋2 個 Hall 接 ESP32」草案：全部 Hall 集中到第 4 片 MCP，ESP32 不再直接接 Hall。完整腳位與初始化暫存器見 [接線表](wiring.md)。TCA9548A 不在採購或基準架構內。

## 為何保留電平轉換

Microchip DS20001952D 指定 MCP23017 的 GPA7、GPB7 只可作輸出；其 GPIO、SDA、SCL、/RESET 高電位門檻為 0.8×VDD。5V 時門檻為 4V，不能把 3.3V 高電位當成保證可辨識。本版將 A7/B7 用於馬達或輸出低，Hall 避開它們。這是原廠 IC 的規格，不代表已驗證 P009 板上晶片真偽、接線或上拉。[Microchip 資料表，第 1、4 頁](https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/MCP23017-Data-Sheet-DS20001952.pdf)

ESP32 採 3.3V 邏輯，5V Hall、5V SDA/SCL、12V 馬達電源均不可直接接 GPIO。開發板的 5V/VIN 輸入路徑另須實板確認；晶片資料表不能證明第三方開發板可承受某一 VIN。[Espressif ESP32 資料表](https://www.espressif.com/sites/default/files/documentation/esp32_datasheet_en.pdf)

## 電源與保護基準

```text
經實測確認的 PD/QC 電源＋誘騙線，設定 12V
  → 合適接頭 → 靠近輸入的保險絲／主電源開關 → 12V 輸入節點
      ├→ 單片 P007 降壓 → 5V 邏輯
      │    ├→ P008 已確認可用的 5V 電源腳 → 板上 3.3V
      │    ├→ 四片 MCP、十片 KY-003、P011 HV
      │    └→ P011 LV 接 ESP32 3.3V
      └→ 獨立、可立即操作的馬達電源切斷 → 12V_MOTOR
           └→ 十顆馬達共用正端＋各 ULN2003 的 COM
所有地線相接；馬達大電流回流另走適當導線回到電源分配點
```

以上是待完成的保護設計，並非聲稱已有保險絲、開關或合格配線。這些物品未在此次明細列出，先盤點與確認額定值，必要時再決定新增採購。

- 原有 PD/QC 線是否可在所配電源上穩定協商 12V、極性、額定電流、重上電設定及 5.5×2.5/2.1mm 配合均未驗證。不可用「可調」或插得進去代替驗證。
- P003 與 P006 是接頭轉接件，不是穩壓器。不可將 12V 接到 ESP32、MCP 或 KY-003。
- P007 的「5A」是賣家標示。IC、電感、接頭、散熱、紋波與連續輸出能力均未驗證；不以 5A 當成本案保證值。
- 電源線、端子、接頭、開關及保險絲須按最弱環節、線長、壓降與實測最大電流選定。未知線規杜邦線不作十馬達主電源匯流排。
- ULN2003 為低側電流驅動；線圈正端及 COM 接同一 12V_MOTOR，GND/E 接地。COM 是感性負載續流二極體的共陰極，不能接 5V 邏輯。板上「VCC」是否真的連到 COM/馬達正端，須量測確認。[TI ULN2003A 資料表，Pin Functions、§7.4.1](https://www.ti.com/lit/ds/symlink/uln2003a.pdf)
- 開關切斷的是馬達分支上游供電；不要另外切斷線圈與續流二極體之間的回路。電感能量、開關突波及局部儲能電容的放電仍須驗證。不要帶電拔馬達插頭。
- USB 與外部 5V 不可在未確認板上隔離的情況下同接。燒錄先關馬達電源並切離外部 5V；避免經 GPIO、電平轉換板或 USB 回灌到已斷電的電源域。

## 功率估算與尚未知道的數字

上游的電流測量來自 Nano／ESP-01／客製 PCB，不適用於本版的功耗保證。12V 也不是馬達外殼溫度、供電電流或可持續運轉時間的保證。

1. 斷電量測每顆馬達共同端到四個線圈端的電阻，確認無短路或異常差異。
2. 每相穩態電流可先用 `(V_motor − ULN 壓降) / R_coil` 估算；實際仍以相電流與驅動溫度驗證。半步常有一相、兩相交替通電；測試最大負載應含兩相通電狀態。
3. 12V 輸入預算包含所有同時通電線圈、5V 負載經降壓後的輸入功率、損耗及餘量。避免把「每通道 500mA」讀成 ULN 整板每路可同時長期承載的額定值；封裝總耗散和占空比也有限制。[TI 熱限制與占空比曲線](https://www.ti.com/lit/ds/symlink/uln2003a.pdf)
4. 量測空載、待命、單馬達、分批與十馬達、Wi-Fi 活動時的最低電壓和峰值電流。上電電容浪湧與多線圈切換的負載階躍要另外觀察，電表平均值可能看不到。
5. 同時運轉數先限制為 1，取得證據後逐步增加。沒有電流、壓降與熱測試前，不宣稱十馬達可同步滿載。

Espressif 建議晶片 3.3V 電源具至少 500mA 能力及適當去耦；無線發射可造成瞬間負載增加。這不是整機只需 500mA，也不是對 P008 板上穩壓器的保證。[硬體設計指引：Power Supply](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32/schematic-checklist.html#power-supply)

## 啟動、故障與停止

必須先讓 5V 控制電路完成初始化，確認所有驅動輸入低，再接通 12V_MOTOR。

- ESP32 重啟不等於 MCP 重啟；MCP 可能保持先前輸出。新韌體在啟動後先保持 /RESET 低，待使用者於馬達電源關閉時下 `INIT POWER_OFF`，才執行至少 10µs 的重設脈衝並釋放，建立已知 BANK/輸出狀態。ESP32 尚未執行程式前的瞬間仍須靠硬體處理。
- 若 P009 沒有引出 /RESET，先找可靠測點／確認焊線方式，或在馬達電源切斷下實際重啟控制電源。不能在文件上假設「有 reset」就略過接線。
- 遇到 I²C NACK、匯流排卡住、Hall 逾時、位置無效或主控重啟，軟體應停止排程並嘗試清零。清零需要通訊成功，不能當成失效安全機制。
- 共享 /RESET 有助於恢復 MCP，但 GPIO23 在 ESP32 reset 期間通常不是持續拉低；也不能保證在 brownout 時所有電源域同步。若 MCP 仍有電，輸出可能維持導通。
- 轉換板上拉會在 ESP32 尚未設定 GPIO23 時釋放 /RESET。馬達輸入浮接／MCP reset 時的關閉狀態必須實測，必要時補下拉；不能靠「程式啟動後會清零」保證上電安全。
- 有卡住、異味、異常升溫、電壓下降或非預期轉動時，立刻用實體切斷 12V_MOTOR。先排除原因，再斷馬達電重新初始化與歸零。
- 現階段只做有人看守的桌上驗證。無人值守前，仍須設計並驗證獨立於 I²C／韌體的預設關閉互鎖或硬體看門狗切斷；本 BOM 沒有宣稱已具備它。

## 韌體與機構的交界

- 邏輯字元索引固定為左到右 0–9，對應線材標籤 U0–U9。
- 每個字元四個邏輯相位 PH1–PH4 是 nibble bit0–3，實體 IN／馬達插座順序須量測後再固定。
- 上游 `unit/unit.ino` 使用 `STEPS=2038` 與全步 `Stepper`，不是此批馬達的實測值。半步不能直接沿用全步的數字或 offset。
- 每顆需記錄方向、Hall 有效電位、穩定邊緣、每圈步數與空白頁偏移，並儲存韌體可設定的參數。45 等分不一定是整數步；本版以整圈絕對位置換算避免每字元截斷累積，未提供 45 個獨立槽位校準表。
- 同一圈內定位不等於多圈都準；驗證所有 45 字元、跨圈及反覆歸零。不要只看能轉一圈就宣布齒比校準完成。
