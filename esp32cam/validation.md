# NodeMCU ESP-32S＋Mega2560 Pro 驗證與實機驗收

## 2026-11-01：舊版 OTA 中止與 1.3.1 修正

使用者回報 1.2.0 在開始上傳約 1～3 秒後出現「更新期間 Mega 失聯或停止狀態已改變」。關閉其他控制頁後，以 mDNS 確認實板位址為 `192.168.68.62`（`splitflap.local`），先前 `.66` 已屬其他設備。使用目前管理密碼正常驗證，不記錄密碼或登入憑證。

- 更新前連續 20 次讀取：1.2.0、Mega 在線、最大快照年齡 445ms，停止／未 ARM、無忙碌、儲存、監看、不確定或 USB 接管。現場為 **10 位 U0～U9**，保留使用者設定。
- 封裝／SHA-256 校驗及正常 STOP 確認後，以 2048 bytes／60ms 單次慢速上傳 1.3.0。傳輸約 32 秒到 100%，最終 HTTP 400 回覆同一錯誤；**不代表刷入成功，沒有自動重試**。
- 更新後仍是 1.2.0、boot 不變，Mega 在線、停止、未 ARM、無不確定狀態。十組配置與備份一致，已保存最後顯示歷史；未發送 ARM／HOME／顯示／校準命令。
- 舊版將完整快照年齡 >1500ms 與真正失聯合併成同一錯誤。Flash 擦寫會影響任務／UART 接收，為本次軟體調查方向；沒有失敗瞬間快照，不能宣稱已證實唯一原因。參考 [Espressif SPI Flash concurrency](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/spi_flash/spi_flash_concurrency.html)。
- 1.3.1 在每次實際 Flash 寫入後等待新的完整狀態，最多 2500ms；未收到時不繼續寫入。真斷線／換 session／停止狀態改變／USB 或配置改變仍立即中止，並提供不同錯誤訊息。沒有放寬 1500ms 的可寫入狀態新鮮度。

## 2026-10-31：1.2.1 修正反覆登入

使用者回報登入後仍頻繁出現瀏覽器登入視窗。確認 Arduino-ESP32 3.3.12 的 WebServer 僅保存一組 nonce／opaque，而每次 `requestAuthentication` 都重生兩者。其他客戶端的未登入請求因而使既有登入失效；舊頁面每秒重試，會持續觸發登入視窗。本次背景唯讀觀察也觸發此問題，已停止；觀察只收到 36 次無通訊錯誤的進度回報，沒有完成十分鐘驗收。

- 正式 `DigestServer` 為本次開機保留同一組 challenge，仍由原 WebServer 檢查目前管理密碼；重開機產生新 token。
- 頁面在 HTTP 401 時先處理登入失效，再解析資料；停止背景輪詢與可見性重試、清除 OTA ticket，顯示「重新登入」。每次手動重試只發出一個查詢，成功後恢復操作；文字／JSON 兩類 401 都涵蓋。
- 固定核心及板型不變，版本升為 1.2.1；僅需更新 ESP32。

## 2026-10-31：P011 冒煙後的主控存活檢查

使用者回報 P011 的 VCCB 供電處短路冒煙，VCCB 接 LM2596 標稱 5V、VCCA 接 ESP32 3V3；事故當時 Mega 是以 5V 接 VIN。後續使用者確認 P011、ESP32、Mega、LM2596 OUT− 四者共地，並於輸出與主控／P011 分離後量得 LM2596 OUT+ 對 OUT− 為 5V。實際短路兩端、模組腳序、事故當下極性與瞬態尚未釐清，不將上述接法直接判定為事故原因。

檢查前，使用者已將外部電源、馬達 12V、P011 的全部電源／訊號線及其他外接線與兩塊主控分離。使用者回報兩板本體沒有焦味；斷電量測 Mega 5V–GND 初讀 169、複測無限大，ESP32 5V–GND／3V3–GND 均無限大。這些電阻讀值只作為上電前篩查，不能證明所有元件完好。

## 手機網頁流程

隔離 Chrome／Playwright 1.62.1，390×844 手機尺寸及 1100×900 桌面尺寸，正式 HTML 連本機模擬 Mega。七組流程通過，未捕捉到 JavaScript 例外：

1. 未登入 API 拒絕；登入後手動記錄 Z、ARM、顯示 Ä；拒絕超長文字，未校時禁止啟動時鐘。
2. 三位依序 U7→U0→U2、手動定位、äA 正規化及補空白；拒絕 ß／中文，1～3 位不提供時鐘格式。
3. 五位 HELLO、手機校時、HH:MM、關閉／重開頁面保留已啟動工作、暫停及可用日期格式。
4. Wi-Fi 表單、匯出不含密碼／CSRF、非法重複位置整份拒絕、有效匯入、離線重連與重啟後全部未 ARM。
5. OTA 先 STOP；截斷檔、SHA-256 錯誤拒絕且不重啟；失敗訊息可重新準備；有效檔模擬更新／重啟，手機與桌面沒有頁面橫向溢出。
6. 首次無 Mega 時可輸入／保存 Wi-Fi，重新載入保留；Mega 隨後連線不覆寫使用者正在輸入的 SSID。馬達控制保持停用；維護時按鈕與 API 均拒絕網路更改。
7. 調整 SPEED／ACCEL 後字元 Ä、定位與 ARM 保留；四張 SVG 經登入載入並解碼成功、手機頁面無橫向溢出；重開機顯示 HELLO 歷史但不自動 ARM，核對後一次操作完成 SETTEXT 與 ARM。

## 已有實機紀錄

使用者先前回報 U0 USB 單顆手動測試數輪無偏移：SPEED=800、ACCEL=800、REVSTEPS=4096、OFFSET=0、DIR=1、ORDER=1234、POLARITY=LOW，SHOW Z 後為 MANUAL／index 26／error=none。原始紀錄見 [Mega 驗證](../mega2560/validation.md)。這不代表本次 ESP32、其餘九位或 Hall 已通過。

2026-10-25 後續 USB 排查：使用者確認 CP2102 已與 ESP32 完全分離、只接電腦 USB。Windows 顯示 `VID_10C4&PID_EA60`、錯誤碼 28，修復前無 COM。Silicon Labs 網站拒絕工具下載，改用 Microsoft Update Catalog 的 11.5.0.417 AMD64 套件；官方 SHA-256 與 Microsoft 硬體相容簽章驗證通過，安裝成功。裝置狀態 OK，專案查詢回 `COM4 serial Serial Port (USB) Unknown`。此結果只確認 CP2102 驅動／USB 列舉；未開啟 COM、驗 ESP32 UART、重新接線或燒錄。ESP32 的 VCC／5V 實際接腳仍待確認。

之後使用者回報已成功燒錄 ESP32，並可進入手機網頁的「裝置設定」；家用 Wi-Fi 保存按鈕被停用。程式重現為舊版 1.0.0 將網路保存誤綁到 Mega 連線條件，1.0.1 已修正並通過上述離線首次設定測試；後續實板已取得家用網路 IP，且可從電腦到達 HTTP 登入入口。

2026-10-25 實機 UART 排查：使用者量得 P011 VCCA=3.3V、VCCB=5V、A1=3.3V、B1=5V。先將供電整理為 Mega 僅由電腦 USB 供電、ESP32 由 LM2596 5V 供電，移除 Mega 外部 5V，馬達分支保持關閉。直接讀 COM3，確認板上開機訊息為 `Mega panel + ESP32 link v1`，U0 未 ARM、定位為 NONE；COM4 起初回報 `Mega=offline`。

所有未勾選項目仍待現場執行，完成時記錄板號、參數、日期與結果。

- [ ] **供電**：關馬達分支，拔 Mega USB，空載調 LM2596 5.0V 後才接兩板 5V 腳；先不接四條 UART 訊號線。量 P011 VCCA／A0／A1 約 3.3V、VCCB／B0／B1 約 5V，核對共地；再關電接訊號。兩板負載時量 5V、3V3 與壓降。Mega 接電腦 USB 前須先拔外部 5V 與四條 UART 訊號線，完成後拔 USB、關控制電源再復原。
- [ ] **燒錄／安全開機**：先更新 Mega，再經 CP2102 更新 ESP32。GPIO0 跳線移除、RESET 後取得 ACCESS；兩板開機均不轉、不 ARM。
- [ ] **板間 UART**：以短跳線接 GPIO13→P011 A0／B0→D19、D18→B1／A1→GPIO14，兩板都供電；先不開馬達分支，以 115200 連線持續讀狀態至少十分鐘，確認不中斷，再確認 U0 運動時查詢不會停止馬達。此項是現有轉換板的實板驗證，不能用主機串列模擬代替。
- [ ] **首次手機登入**：直連 AP、設備隨機密碼及 admin Digest 登入，未登入／錯 CSRF 操作拒絕。家用 Wi-Fi、IP、splitflap.local、重連及 AP 備援可用。
- [ ] **U0 手動定位**：只啟用一位；記錄實際字元、ARM，先短距離再跨圈，核對目標、45 字元及重複停點；確認 STOP 釋放線圈並使位置失效。
- [ ] **手機離線**：文字移動中關頁面應完成；校時啟動時鐘後關閉頁面，跨多個分鐘確認仍運作。忙碌跨分鐘時完成後只追最新目標。
- [ ] **兩秒失聯**：保留兩板供電，遠端運動時分別斷開 ESP→Mega、Mega→ESP 及雙向 UART，確認 Mega 於租期到期停止、解除 ARM／定位；另測 ESP32 RESET，確認重連不重播、須重新定位並啟用。現有轉換板不假設斷電隔離，不保留訊號線熱拔單側電源。獨立 USB 調機先依接線表拆除板間訊號與外部 5V。
- [ ] **USB 接管**：USB 控制後網頁提示接管；時計暫停；Claim／STOP 後不會自行恢復運動。
- [ ] **持久化**：驗舊 EEPROM 5000／400 升級後為 800／800，自訂校準不變；調速保存後定位與 ARM 保留。保存校準、位數／順序、Wi-Fi／偏好及最後字元後重開兩板；設定與歷史恢復，可信定位／ARM／自動顯示不恢復。核對歷史字元，一次確認後才可轉動；移動中斷電不能誤當已到目標。匯入先拒絕非法檔，再確認有效檔完整套用。
- [ ] **其餘位置**：逐顆驗 U1～U9 的 IN1～IN4、電源與運動，再測實際使用位數、非連續順序與整串文字；不同目標須一起起步、各自停止、相同字元不動；測並行 STOP／故障後全組停轉及負載壓降，未啟用輸出維持關閉。
- [ ] **磁鐵／Hall**：裝磁鐵後量有效極性、原始／去抖狀態、HOME、三圈 MEASURE、OFFSET 與 CYCLE；本次沒有真實磁鐵驗收。
- [ ] **實際 OTA**：停止確認後先驗錯檔拒絕，再測有效更新；測中斷上傳可重試、上傳時 UART 仍有心跳、Mega 失聯／USB 啟動會中止。更新後設定保留、仍需定位與 ARM；中斷供電測試在已停止且備有 USB 復原方式時做。
- [ ] **長時間負載**：實際多位文字／時鐘、5V 穩壓、接點壓降、馬達／ULN／降壓器溫升、抗干擾與實體馬達支路切斷。

軟體 STOP 不能切斷 12V，也不能在控制器／供電故障時保證關閉。接線依 [逐線表](wiring.md)與兩張圖；新位置先逐顆確認，再擴充。
