## 從 1.2.0／1.2.1 升級

- 只需更新 ESP32，使用 `dist/splitflap-esp32s.sffw`；Mega 韌體與接線不變。
- 保留既有 Wi-Fi、設備直連密碼、管理密碼與最後字元。舊版 NVS 記錄驗證成功後遷移至新記錄，不因資料結構變更而重設密碼。
- 更新後關閉舊分頁並重新開啟控制頁，以原管理密碼在頁面內登入一次。此後關頁或復電不會退出登入。
- 首次升級不會自動轉動。先設定實際位數，再完成一次歸零校準；確認保存後才自動開啟復電恢復。
- 舊版非連續安裝清單不再支援網頁操作。先在位數設定選擇 U0 起的連續位置；不會默默將 U7 的校準搬到 U0。

## 登入與網路

開啟裝置目前的區網 IP、`http://splitflap.local/`，或連上設備直連 Wi-Fi 後開 `http://192.168.4.1/`。帳號為 `admin`，使用現有管理密碼。首次裝置資料可從 USB 串列 `ACCESS` 取得；密碼不放入設定備份。

登入採頁面表單與持久 Cookie，不使用瀏覽器原生登入視窗。最多記住 8 個瀏覽器登入，第 9 個新登入會替換最舊的一個；Cookie 有瀏覽器保存期限，開頁會延長。登出只移除目前登入，改管理密碼或重設網路會撤銷全部登入。瀏覽器清除資料或改用另一個網址時可能需要再次登入。

登入失效時停止自動查詢，保留未送出的表單，顯示登入畫面；重新登入後不會重送舊動作。網頁與 API 適用設備直連／可信任區網，沿用 HTTP，不新增公網服務。

「裝置設定 → 網路與登入」可在 Mega 尚未連線時保存 Wi-Fi；操作或校準期間則等待完成。直連網路仍保留。修改網路會暫停自動顯示。

## 位數與直接操作

「裝置設定 → 安裝與復電」設定 1～10 位：N 位固定使用 U0 至 U(N−1)。顯示、校準、單元測試都使用同一範圍，沒有額外啟用或自訂排列。

在「顯示」填文字並送出。韌體會自動完成必要授權；已確認校準而定位失效時，先歸零再顯示。尚未校準可先走歸零流程，或在「手動記錄目前字元」填入實際看到的字元。記錄本身不轉動。

支援空白、A–Z、Ä Ö Ü、0–9、`: . - ? !`；小寫轉大寫，`_` 代表空白。短文字依對齊補空白，過長或不支援的字元拒絕。字元順序維持 45 片原配置。

「單元測試」直接操作選定位置；全部測試只涵蓋設定的位數。前進一片、指定字元與循環需要可信定位；步進／整圈／量測不會覆蓋正常顯示歷史。內部 ARM 與心跳保護仍保留，USB 人工指令也維持原本流程。

## 歸零與空白偏移

1. 到「裝置設定 → 歸零與空白偏移」，按「全部歸零並校準」。所有已設定位置沿用原偏移，同時歸零，各自到位停止。
2. 選擇位置。可以輸入偏移步數並歸零預覽，或前進 1／10／100 步，觀察空白頁是否完整落下。微調只前進，偏移以每圈步數取餘數。
3. 確認各位空白頁後按「確認空白並永久保存」。設備再執行一次全部歸零，成功後寫 Mega EEPROM，最後保存 ESP32 校準確認。
4. 「取消校準」恢復開始前參數；預覽不會先覆寫永久偏移。停止或失敗後若要繼續微調，先重新執行數字歸零預覽。

一般歸零、停止或復電不清除已保存偏移。修改圈步數、方向、相序、極性或新增位置後，相關位置須重新確認；速度／加減速度不影響校準確認。原 U0 的歷史 OFFSET=273 可作為同一機構的參考，不能套用其他位置。

任一位置找不到霍爾、失聯、逾時或按停止，整個流程中止，不自動反覆重試。網頁顯示原因與各位進度。關閉網頁不會取消已接受的流程。

## 復電恢復

首次完成全部位置校準確認後，自動開啟復電恢復；可在設定頁關閉，之後再次校準不會覆蓋這個手動選擇。

正常上電：最多等待 Mega 30 秒 → 全部歸零 → 恢復顯示。文字使用最後完成值；時鐘取得時間後顯示現在時間；輪播從上次完成項目繼續。未取得時間或在指定顯示時段外，先保留已保存畫面。沒有歷史的單元使用空白。

OTA／軟體重啟、異常重啟、校準無效或等待逾時不會自動轉動。硬體重設若由晶片回報為正常上電，同樣採上電流程。停止只會在使用者再次下指令或下次符合條件的正常上電後恢復；停止／暫停會保存自動模式已暫停的意圖。

## 時鐘、日期、星期與輪播

預設台北 UTC+08:00，支援網路 NTP 與手機校時；沒有外接 RTC，完全斷電後需重新取得時間。

| 內容 | 格式範例 | 最少位數 |
| --- | --- | --- |
| 單獨時／分／秒 | HH、MM、SS | 2 |
| 24 小時 | HHMM、HH:MM | 4／5 |
| 含秒時間 | HHMMSS、HH:MM:SS | 6／8 |
| 12 小時 | hhmm、hh:mm；可加 AM／PM | 4 起 |
| 12 小時含秒與 AM／PM | hh:mm:ssAP | 10 |
| 月日／日月 | MMDD、MM-DD、DDMM、DD-MM | 4／5 |
| 含年份 | YYMMDD、YYYYMMDD、YYYY-MM-DD、DD-MM-YYYY | 6／8／10 |
| 星期 | MON 或 WEDNESDAY 等英文 | 3／9 |

格式依位數篩選，提供字元預覽、小時前導零與對齊設定。「保存設定」不開始轉動；「保存並開始」會準備定位後開始自動顯示。

輪播最多 8 項，可混合時鐘、日期、星期、文字，調整順序、對齊及停留秒數（10～3600 秒，預設 30 秒）。停留時間從該項翻頁完成後起算。可限制每日顯示時段，包括跨午夜；起訖相同代表全天。時段外停留最後畫面。

含秒格式依機構速度盡力更新，不能保證逐秒到位。忙碌時不排隊累積舊時間，完成後重算最新內容；相同字元不轉動。關閉手機頁面不會停止排程。

## 保存與備份

- Mega 雙槽 EEPROM：位數對應的安裝清單、十組機構參數與偏移，沿用版本／CRC／提交標記。
- ESP32 NVS：網路、登入記錄、顯示偏好、校準確認、復電設定、最後畫面及輪播完成項目。
- 正常固定文字完成後保存；歸零／微調／驅動測試不覆蓋顯示歷史。動態畫面最多每分鐘寫一次；秒數由目前時間推算，不逐秒寫 Flash。儲存失敗顯示狀態並限速重試。
- 匯出 schema 2，包含 `mega.digits`、十組 calibration 與 display 偏好，沒有密碼、登入憑證、實際位置或 ARM。可匯入連續位置的 schema 1，非連續清單明確拒絕。
- 跨兩板保存先完成 Mega，再保存 ESP32；後者失敗會回報失敗，不將部分完成標成成功。

## 建置、更新與測試

硬體為 classic ESP32／ESP-WROOM-32、4MB、DIO／40MHz、無 PSRAM；固定 Arduino-ESP32 3.3.12，FQBN 使用 `esp32:esp32:esp32:PartitionScheme=min_spiffs,FlashSize=4M,FlashMode=dio,FlashFreq=40,PSRAM=disabled`。

```powershell
python esp32cam/tools/dev.py build
python esp32cam/tools/dev.py test
python esp32cam/tools/dev.py test-web
```

產物為 `dist/splitflap-esp32s.sffw`、`.bin` 與 `firmware.json`。OTA 先「停止並準備更新」，取得 Mega 停止確認後上傳；驗證板型、長度、協定與 SHA-256。新板更新檔沿用 1.2.0 的封裝；舊 CAM 產物仍會拒絕。1.3.1 每次實際寫入 Flash 後等待新的完整 Mega 狀態，再繼續寫入，更新可能需要數分鐘。

若現場 1.2.0 在上傳後回報「更新期間 Mega 失聯或停止狀態已改變」，新版尚未執行，無法自行修正舊版的上傳流程。本次慢速上傳也被舊版拒絕，改採一次 USB 更新；不要將上傳到 100% 當成安裝成功，需確認設備回報新版及正常重新連線。

`tools/ota_upload.py --url http://splitflap.local --version 1.3.1` 提供可選的慢速 LAN 更新與更新後比對，先以環境變數 `SF_DEVICE_ADMIN_PASSWORD` 提供密碼。工具會備份設定、正常準備 STOP、驗證封裝、單次上傳並核對版本及設定；不自動重試失敗上傳、不啟動馬達。它仍受設備原有檢查限制，不能解決本次舊版拒絕更新的情況。

USB 初次燒錄與供電切換依[接線指南](wiring.md)；一般網頁更新不用接 USB。若需板上 USB，仍使用既有 `ports`／`upload-monitor --port COMx` 工具。Mega USB 操作見[獨立指南](../mega2560/README.md)。

瀏覽器測試使用獨立 Chrome 與本機 HTTP 模擬器，沒有操作實板。結果、截圖放在 `test/.build/`；不能代替實板運動、斷電與 Flash 更新驗收。現場依序驗收登入 → U0 校準 → 文字 → 復電 → 多位 → 時鐘與輪播。
